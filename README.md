# Dot Abyss X — native Live2D scenario player

A faithful, native re-implementation of *ドットアビス X (Dot Abyss X)*'s Live2D scenario
playback in Unity (Cubism SDK), for Windows and Android, driven by the game's **own
extracted data**. It ships with a Python extraction/build pipeline and a `da` CLI that
regenerates everything when the game updates.

## What this is

The whole effort lives in one repo:

- **`unity/`** — a Unity `6000.3.8f1` URP project: the player (`Assets/DA_Runtime/`) plus the
  editor build pipeline (`Assets/Editor/`).
- **`tools/`** — a Python pipeline (`pipeline/`) and the **`da`** CLI (`da.py`) that
  re-extract and rebuild everything from the game's files.
- **`docs/`** — architecture, the reverse-engineered playback behavior, and a build log.
- **`data/`, `build/`** — derived, machine-local, and **git-ignored** (regenerated by `da`).

See [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) for how the pieces fit together.

## Setup

1. Install **Unity 6000.3.8f1** (URP). Set `unityExe` in `config.json` (or in
   `config.local.json`) to your `Unity.exe` if it isn't at the default path.
2. Install the Python toolchain and dependencies with **uv**:
   ```sh
   uv sync           # creates .venv and installs deps from pyproject.toml
   ```
   (Or, without uv: `pip install -r tools/requirements.txt`.)
3. Install the **Live2D Cubism SDK** into `unity/Assets/Live2D/Cubism/`, and fetch the tools:
   ```sh
   uv run python tools/fetch_tools.py
   ```
4. Generate a throwaway **Android debug keystore** (only needed for Android builds):
   ```sh
   keytool -genkeypair -v -keystore keystore/debug.keystore -alias androiddebugkey \
     -storepass android -keypass android -keyalg RSA -keysize 2048 -validity 10000 \
     -dname "CN=Android Debug,O=Android,C=US"
   ```
5. **Bring your own game data.** Put your unpacked APK at `data/game` (a directory or a
   junction/symlink). To point elsewhere without editing `config.json`, create
   `config.local.json`:
   ```json
   { "game": "D:/path/to/unpacked_apk" }
   ```

## The `da` CLI

Run `tools\da <command>` (Windows) or `uv run python tools/da.py <command>`.

| command | what it does |
|---|---|
| `da paths` | print every resolved path (sanity check) |
| `da extract` | bundles → images + text + live2d, then bucket images |
| `da audio` | ACB/AWB → **OGG** → `cue_index.json` (parallel decode; `--force`, `--workers N`) |
| `da encode [args]` | re-encode any leftover WAV → OGG (`--limit N`, `--keep-wav`, `--workers N`, `--reindex-only`) |
| `da scenes` | scenario scripts → `_viewer/scenes_v2.json` |
| `da rip` | **headless** AssetRipper over the `l2d_*` model bundles → `data/ripped` (~5 min) |
| `da live2d` | rebuild `Live2DOutput/<model>/{moc3,textures,model3.json}` from the cache (default = only new models; `--all`, `--models a,b`, `--rescan`) |
| `da models` | assemble `unity/Assets/Models` from `live2d` + `ripped` |
| `da unity <step>` | Unity batchmode: `setup` · `windows` · `android` · `bundles` · `validate`, or `Class.Method` |
| `da dump` | Cpp2IL → `data/dump` (only when the game **code** changes) |
| `da update [--game DIR] [--no-rip]` | extract → audio → scenes → **rip → live2d** → models → `unity setup` |

`da unity` aliases: `setup`→`DA_Build.FullSetup`, `windows`→`BuildWindows`,
`android`→`BuildAndroid`, `bundles`→`WinBundleTest`, `validate`→`DA_Setup.ValidateAll`.

## Updating when the game gets a new version

1. Point `data/game` at the new unpacked APK (junction, or `da update --game <folder>`).
   New Live2D models live in `files/UnityCache/Shared`.
2. `da update` — regenerates everything: extracted assets, OGG audio, scenes, a headless
   targeted rip, `Live2DOutput` for any **new** models (auto-detected from the cache), the
   Unity models, and Unity setup. Add `--no-rip` for a content-only patch (no new characters).
3. Rebuild players: `da unity android` (APK) and/or `da unity windows` (desktop).
4. Deploy to device: put `data/bundles/` + `data/extracted/audio/` (+`cue_index.json`) +
   `data/extracted/images/` in a folder named `dotabyss_extracted` on the device. It can go
   anywhere the app can read — the app-specific folder (`Android/data/<pkg>/files`), or an
   easier-to-reach public folder like `Download/dotabyss_extracted`. Then point the player at
   it in-app (see the folder picker under **Notes**); common locations are auto-detected.

`da dump` (Cpp2IL) is only needed when the game's **code** changed; content updates don't.

## Audio

Decoded audio is stored as **OGG (Vorbis)**, not WAV — voice at `-q:a 3 -ac 1` (mono),
BGM/SE at `-q:a 5`. This cuts audio from ~15.5 GB (WAV) to ~1.5 GB with no audible loss.
Quality is configurable under `audio` in `config.json`. The Unity `AudioRouter` picks the
decoder by file extension (OGG/WAV).

## Notes

- Cubism models render **only** through the URP `CubismRenderPassFeature` (Built-in = blank).
- The mosaic/censorship overlay drawables (`Mosaic*`) can be hidden via the player's mosaic
  toggle. This affects only the rendering of **your own local copy** of assets you already own;
  it distributes nothing.
- The dialogue box can be hidden for an unobstructed view of the art via the **TEXT** button
  (top bar) or the **H** key. The AUTO/SKIP/☰ controls stay visible, and taps still advance.
- A **Lite (performance)** toggle (behind ☰) trades the cinematic look for speed — it drops
  bloom and lowers the render scale. It defaults to **Lite on mobile / Full on desktop** and
  the choice is remembered per device. Use Lite on low-end Android for a smoother experience.
- **Assets folder** (behind ☰): choose where the `dotabyss_extracted` data (audio + bundles)
  lives. The picker lists auto-detected folders (on Android: `Download/`, `Documents/`, the
  sdcard root, and the app-specific folder); or type/paste a custom path and press **Apply**.
  The choice is remembered per device (`DAConfig` → `PlayerPrefs`), so you no longer have to
  drop files into the hard-to-reach `Android/data/<pkg>/files` folder. On Android 11+, tap
  **Grant storage access** once (opens the system "All files access" page) so the app can read
  public folders; **Reset** returns to auto-detection. `scenes.json` ships inside the APK, so
  scene playback works even before you point at a data folder.
